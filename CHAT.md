# Каталог SSR и чат

Каталог `/catalog`, категории и подкатегории теперь отдают товары в исходном HTML. Сервер параллельно получает категории и соответствующую страницу товаров, учитывая фильтры и сортировку. При гидратации тот же список используется без повторной загрузки; дальнейшие переходы работают через API. Пагинация содержит обычные ссылки и работает без JavaScript. Неизвестный раздел и страница за пределами списка дают 404; недоступность API — 503 с `noindex`.

Окно чата доступно на публичных страницах, раздел менеджера — `/admin/chats`. Внешний вид использует типографику и цвета действующего сайта. Фотографии из исходной пересылки не были приложены, поэтому точное совпадение с ними не проверялось.

## Запуск

`npm ci`, `npm run build`, `npm start`. Переменные `SITE_URL`, `API_SERVER_URL`, `PORT`, `HOST` описаны в `SSR.md`. По умолчанию WebSocket использует текущий домен и `/api/chat/socket.io`. Для отдельного публичного сервера чата можно задать `VITE_CHAT_URL` перед сборкой. Node-сервер production передаёт Upgrade на `API_SERVER_URL`; внешний nginx также должен пропускать Upgrade. Схема БД, SMTP и пример nginx описаны в `CHAT.md` backend.

Раздел чатов менеджера и виджет загружаются отдельными модулями. Чат не выполняется во время серверного рендеринга каталога.

## Проверки

```sh
npm test
npm run lint
npm run build
npx playwright install chromium
npx playwright test
```

Браузерные тесты ожидают запущенные production frontend на `127.0.0.1:4173` и API на `127.0.0.1:4191` с отдельной локальной базой, минимум 21 товаром, разделом `vagonnye-zapchasti` и товаром «Авторежим 265А-4». Используется тестовый стандартный вход `admin/admin`. Не применять эти учётные данные к рабочему серверу. Тесты проверяют серверный HTML без JavaScript, пагинацию, гидратацию, переписку между двумя сессиями браузера, восстановление после offline и размеры мобильных интерфейсов.

Если Chrome уже установлен, задать `PLAYWRIGHT_CHANNEL=chrome` вместо скачивания Chromium. Альтернативный локальный адрес frontend задаётся через `CHAT_TEST_FRONTEND_URL`.

Для мобильного предпросмотра использовать порт `4173`. Порт `4190` входит в список запрещённых портов Fetch и может ломать запросы через промежуточный предпросмотр: https://fetch.spec.whatwg.org/#port-blocking. При смене порта обновить `SITE_URL` frontend и разрешённый origin API.

Дополнительные проверки: пустой ответ прокси при начале чата, сохранение введённых данных и успешная повторная попытка; плашка cookies во вложенном мобильном окне после прокрутки и изменения его высоты. Технические ошибки разбора JSON не показываются посетителю. Высота уведомления ограничена содержащим окном без зависимости от `dvh`.
